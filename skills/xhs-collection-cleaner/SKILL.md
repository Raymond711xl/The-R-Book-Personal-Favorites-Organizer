# 小红书收藏清洗对话工作台

把 Agent 对话作为控制台，把本地状态文件作为可续跑账本。网页只能作为可选结果看板，不能成为完成任务的前提。

固定版本：`v0.1.0`。

## 工作原则

- 默认范围仅为“收藏”，不要读取“赞过”，除非用户明确扩展范围。
- 先盘点，后下载媒体。快速盘点只读取类型、正文长度、图片数、视频时长、互动数据和收藏夹成员关系。
- 始终区分页面标称数、已知数、可访问数、已处理数和不可达数。
- 将精确数据标为“已确认”，将按样本外推的数据标为“样本估算”。
- 不把快速盘点称为 RAG。它是 RAG 或 Markdown 知识库之前的摄取与清洗控制层。
- 生成计划不等于开始执行。批量处理前必须让用户看到范围、预计条数和停止条件。
- 不要求本地桥接程序、常驻服务或网页按钮。只在用户与 Agent 对话时执行任务。

## 意图路由

| 用户意图 | 行为 |
| --- | --- |
| 未说明动作、询问“能做什么” | 展示能力菜单 |
| “盘点”“快速盘点” | 刷新聚合数据并展示完整盘点 |
| “当前进度”“完成多少” | 展示精简进度看板 |
| “生成 N 分钟计划” | 展示时间预算、处理组合和确认入口；不要开工 |
| “开始执行刚才的计划” | 先复述计划范围，再按现有项目脚本执行 |
| “暂停” | 完成当前原子条目，保存断点，然后停止 |
| “继续上次任务” | 读取状态和最近清单，从未完成条目继续 |
| “只处理图片/短视频/P0” | 把条件作为本次计划过滤器，不改变全局范围 |

## 对话流程

1. 检查项目内的收藏快照、采集状态、归档清单和已清洗目录。
2. 读取 [数据契约](references/data-contract.md) 判断可确认与只能估算的指标。
3. 需要最新盘点时运行：

   ```bash
   node <本 Skill 目录>/scripts/build-inventory.mjs --root <项目目录> --output <项目目录>/data/processing-dashboard.json
   ```

4. 按用户意图运行对话渲染器：

   ```bash
   node <本 Skill 目录>/scripts/render-chat.mjs --root <项目目录> --view menu
   node <本 Skill 目录>/scripts/render-chat.mjs --root <项目目录> --view inventory
   node <本 Skill 目录>/scripts/render-chat.mjs --root <项目目录> --view status
   node <本 Skill 目录>/scripts/render-chat.mjs --root <项目目录> --view plan --minutes 90
   ```

5. 直接在对话中呈现渲染结果。遵守 [对话展示协议](references/conversation-ui.md)，不要要求用户打开网页查看核心数据。
6. 生成计划时读取 [处理策略](references/processing-policy.md)。没有分钟数时展示 30、60、90、120 分钟选项。
7. 用户明确开始后才执行。每完成一个条目立即更新状态；收到暂停指令时不要开始下一条。

## 输出要求

- 先给结论和当前状态，再给表格与下一句可用指令。
- 用紧凑标题框、Markdown 表格、进度条和分隔线形成“文字界面”。
- 每次只展示当前意图所需的数据；不要把所有看板一次性倾倒出来。
- 明确标注“已确认”“样本估算”“等待确认”和“正在执行”。
- 不输出 Cookie、`xsec_token`、原始页面 HTML、密码或私有访问 URL。
