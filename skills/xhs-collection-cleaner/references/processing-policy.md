# 处理策略

## 当前阶段

当前以 Agent 对话作为唯一操作入口，确定性脚本负责聚合、排版和状态记录。网页是可选的只读结果看板，不要求本地桥接程序或常驻服务。自动采集、夜间任务、定时调度与第三方知识库发布都属于后续可选阶段。

## 五步工作法

1. **快速盘点**：只读元数据，得到数量、类型、成本和风险。
2. **成本分桶**：把内容分为文字快速、轻图片、重图片和长中短视频。
3. **优先级排序**：结合用户标星、收藏/点赞、主题相关性与可操作性产生 P0/P1/P2。
4. **深度清洗**：按桶调用 OCR、视频转写、结构化摘要和标签；切片与向量索引属于下一阶段。
5. **发布与回顾**：输出平台无关 Markdown，再由其他适配器决定是否进入知识库。

## P0/P1/P2

- P0：约 15%，完整处理，优先形成能立即阅读或执行的知识卡。
- P1：约 35%，标准摘要、标签和关键媒体提取。
- P2：约 50%，先保留标题、链接和元数据，用户选中后再深度处理。

这些比例用于容量规划。只有逐条完成评分后，才能把某条内容真正标记为 P0/P1/P2。

## 对话确认边界

- “生成 N 分钟计划”只生成容量和任务建议，不自动开始。
- “开始执行”必须引用最近一次计划，并先显示目标、过滤条件和停止条件。
- 没有持久化具体 `noteId` 的计划只能称为“容量估算”，不能称为“可执行条目清单”。
- 未接入能力应明确显示“下一阶段”或“未启用”，不能用按钮或话术假装已经执行。
- 任何真实批处理开始前都要显示目标条数、预计媒体量和可恢复断点。
- 网页不得成为确认或续跑任务的唯一入口。

## 状态机

v0.1.0 当前可确认的聚合阶段：

`discovered → fetchable → archived → enriched → published`

完成切片和向量索引后的目标阶段：

`discovered → fetchable → archived → enriched → chunked → embedded → synced`

异常状态独立记录为 `blocked`、`failed` 或 `action-required`，不要让失败条目消失在总数里。
