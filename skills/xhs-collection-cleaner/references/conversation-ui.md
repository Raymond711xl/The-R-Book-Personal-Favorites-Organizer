# 对话展示协议

## 目标

让用户不打开网页也能完成“了解能力、查看数据、生成计划、确认执行、暂停和续跑”。对话是主界面，网页只是可选镜像。

本协议固定于 `xhs-collection-cleaner v0.1.0`。

## 通用结构

每次回复按以下顺序组织：

1. 紧凑标题框：Skill 名称、当前视图、数据时间。
2. 一句话结论：说清当前最重要的数字或状态。
3. 主体：使用 Markdown 表格、短进度条或编号清单。
4. 口径：只展示与本次结果相关的估算和异常。
5. 下一步：给出 2–4 句用户可以直接发送的指令。

不要使用依赖固定超宽窗口的复杂字符表格。标题框可以使用等宽文本；数据列使用 Markdown 表格，以便窄窗口自动换行。

## 能力菜单

用户未指定动作或询问 Skill 能做什么时，展示：

| 能力 | 示例指令 | 默认行为 |
| --- | --- | --- |
| 快速盘点 | “盘点我的收藏” | 只读元数据，不下载媒体 |
| 查看进度 | “现在完成到哪里了？” | 读取账本并显示阶段进度 |
| 分析结构 | “视频和图文各有多少？” | 展示类型、成本与可信度 |
| 生成计划 | “生成一个 90 分钟计划” | 只生成计划，等待确认 |
| 执行计划 | “开始执行刚才的计划” | 复述范围后开始 |
| 暂停任务 | “做完当前这一条后暂停” | 保存断点，不开始下一条 |
| 继续任务 | “继续昨天的计划” | 从最近断点续跑 |
| 条件处理 | “今天只处理图片” | 仅过滤本次任务 |

如果数据文件存在，在菜单上方附一行当前快照：已知数、待归档数、最近更新时间。

## 快速盘点

至少包含：

- 页面标称、已知、可处理、受阻、未解析；
- 图文、视频、未知类型；
- 已归档、已深度清洗、已进入阅读库；
- 视频时长分布的可信度；
- 与当前决策直接相关的风险。

不要把页面标称数当成已抓取数，也不要把样本视频分布写成全量精确分布。

## 分钟计划

标题必须显示“计划预览 · 尚未执行”。主体包含：

- 时间预算；
- 建议目标条数；
- 快速处理与深度处理组合；
- 当前数据能否生成真实条目清单；
- 停止条件；
- 下一步确认指令。

未取得逐条时长时，明确写“容量估算”。只有选出具体 `noteId` 并持久化任务清单后，才称为“可执行条目清单”。

## 执行中

每个进度节点使用：

| 项目 | 当前值 |
| --- | --- |
| 任务 | 计划名称或编号 |
| 已完成 | N / 总数 |
| 当前条目 | 标题或安全短标识 |
| 当前阶段 | fetched / extracted / chunked / reviewed |
| 失败 | 数量与可重试数量 |
| 停止条件 | 条数、时间或“完成当前条目” |
| 最近断点 | 时间 |

长任务不持续刷屏。完成一批或状态发生变化时再汇报。

## 暂停与续跑

暂停结果必须明确说明：

- 当前原子条目是否完成；
- 本批完成、失败、剩余数量；
- 断点写入位置；
- 下次可以直接发送的续跑指令。

续跑前先展示读取到的断点，不能仅凭对话记忆推断进度。
